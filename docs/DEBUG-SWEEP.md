## 5. 점검에서 나온 것 — ✅ 고쳤습니다

**HTTP 메서드가 지침서와 어긋났습니다.** `GUIDELINES.md` §4-1 은 상태를 바꾸는 요청을
`PUT`(켬)·`DELETE`(끔)로 하라고 적고 `setClear` · `setSpecial` · `setLike` 를 예로 드는데,
실제로 그 모양인 것은 `posts/:id/like` 뿐이었고 `favorites` · `vote` · `clear` · `special` 은
**POST** 였습니다. 동작 자체는 멱등했지만(본문에 원하는 상태를 실었습니다), 문서를 보고
`PUT` 을 부르면 **405** 가 났습니다 — 이 점검에서 제가 그렇게 걸렸습니다.

**코드를 문서 쪽으로 옮겼습니다.** `like` 가 이미 그 모양이었고 규칙에 근거가 적혀 있으므로,
나머지 넷을 맞추는 편이 맞습니다.

| 엔드포인트 | 전 | 후 |
|---|---|---|
| `/api/favorites` | `POST {arcadeId}` | `PUT {arcadeId}` (DELETE 는 그대로) |
| `/api/charts/:id/clear` | `POST {cleared}` | `PUT` / `DELETE` (본문 없음) |
| `/api/charts/:id/special` | `POST {special}` | `PUT` / `DELETE` (본문 없음) |
| `/api/charts/:id/vote` | `POST {value\|null}` | `PUT {value}` / `DELETE` (취소) |

호출부(`lib/use-favorites.ts` · `components/ChartDetailPanel.tsx` · `load-test/k6-write.js`)와
테스트 2개도 함께 옮겼고, 지침서 §4-1 에 **지금 이 규칙을 따르는 라우트 표**를 넣어 다음에
같은 어긋남이 생기면 바로 보이게 했습니다.

재검증 (운영 빌드 · 실제 서버):

- 켜기/끄기 10건 전부 200
- 같은 `PUT` 을 두 번 불러도 상태가 같음 (투표 0.5 = 0.5, 즐겨찾기 `[205]`)
- 옛 `POST` 4개는 이제 **405** — 의도된 변경입니다. 출시 전이라 외부 호출자가 없고,
  호환용 별칭을 남기면 같은 혼동이 그대로 남기 때문에 두지 않았습니다
- 비로그인은 여전히 401 · 투표 범위 밖 400 · 클리어 없는 투표 403 (게이트 유지)
- 화면에서 별·클리어·특수패턴을 실제로 눌러 **`PUT`/`DELETE` 로 나가는 것**과 4xx/5xx 0건 확인

## 5-2. 점검 뒤에 이어서 고친 것 — H12 세션 회수

> 이건 이번 점검에서 **나온** 결함이 아닙니다. QA 감사에서 High 로 적어 두고
> "따로 봐야 할 변경" 이라며 미뤘던 항목(H12)인데, 배포 가능 여부를 따지다
> 다시 꺼냈습니다. 세션을 뺏긴 사람이 스스로 할 수 있는 일이 없는 상태로
> 여는 것이 걸렸습니다.

**무엇이 문제였나** — 세션 쿠키는 서명 한 장으로 성립합니다(무상태). 서버에 아무것도
남지 않으니 "이 쿠키는 이제 무효" 라고 말할 자리가 없었습니다. 로그아웃은 내 브라우저의
쿠키를 지우는 것뿐이고, **비밀번호를 바꿔도 남의 기기에 열린 창은 7일을 살았습니다.**

**무엇을 했나** — `players.token_epoch`(`migrate-057`) 한 컬럼. 토큰에 발급 당시의 번호를
함께 봉하고 요청마다 대조합니다. 번호를 올리면 그 계정의 지난 쿠키가 한꺼번에 죽습니다.

| | 전 | 후 |
|---|---|---|
| 세션 판정 | 쿠키의 서명만 | 서명 + `players` 한 줄(`token_epoch`) |
| 토큰이 지는 것 | `{누구, 이름, 관리자, 만료}` | `{누구, 세대, 만료}` — 이름·권한은 매번 DB 에서 |
| 비밀번호 변경 | 다른 기기 세션 유지 | **끊김** (`setPlayerPassword` 가 올림) |
| 탈퇴 | 쿠키는 7일 유효, FK 가 막아 줌 | **다음 요청에 401** |
| 관리자 권한 회수 | `requireAdmin` 만 DB 재확인 | 모든 세션이 DB 를 봄 |
| 본인이 끊는 수단 | 없음 | `DELETE /api/account/sessions` + `/account` 버튼 |

`getSession`·`sessionPlayerId`·`requirePlayer` 가 async 가 되어 **라우트 19개 · 호출 31곳**이
`await` 로 바뀌었습니다. 대신 `adminRow` 와 `/api/auth/session` 의 중복 조회가 사라져
**관리자 경로는 players 조회가 2회에서 1회로 줄었습니다.** 쿠키가 없는 요청은 DB 까지
가지 않으므로 둘러보기만 하는 사람에게는 변화가 없습니다.

재검증 (운영 빌드 · 개발 DB 복제본 · 실제 서버):

| 확인 | 결과 |
|---|---|
| 가입·로그인으로 기기 A·B 세션 | 둘 다 살아 있음 |
| B 가 "다른 기기에서 모두 로그아웃" | 200 + 쿠키 재발급 |
| 끊긴 A 로 조회·쓰기 | 세션 null · **401** |
| 끊은 본인(B 의 새 쿠키) | 그대로 200 |
| 비밀번호 변경 | 그 전의 모든 쿠키가 끊김, 바꾼 본인만 이어짐 |
| 죽은 쿠키로 `/api/auth/session` | `{user:null}` + **Set-Cookie 로 쿠키 삭제** |
| 탈퇴 직후 같은 쿠키 | 만료를 기다리지 않고 즉시 무효 |
| 비로그인 읽기 / 익명 쓰기 | 200 / 401 (그대로) |

**20/20 통과 · 서버 로그 오류 0건.** 실제 크롬에서 `/account` 의 새 버튼을 눌러
`DELETE /api/account/sessions → 200` 과 "끊었습니다." 표시, 그리고 **그 창은 로그인
상태로 남는 것**까지 확인했습니다. 단위 테스트는 `tests/session-revoke.test.ts` 10개.

> ⚠ **운영 배포 시**: `npm run db:migrate` 가 `migrate-057` 을 넣습니다(ALTER ADD COLUMN,
> 기본값 0 — 잠금 없이 끝납니다). 넣지 않고 새 코드를 띄우면 `token_epoch` 이 없어

## 8. 이번에 확인하지 못한 것

- **네이버 지도 SDK 와 CSP.** 로컬에 지도 키가 없어 대체 지도로만 떴습니다. 키를 넣고 콘솔에
  CSP 위반이 없는지 확인해야 합니다 (deploy/README.md 체크리스트).
- **DB 가 죽었을 때의 실제 동작.** 개발 PostgreSQL 을 멈추면 다른 워크트리가 같이 영향을 받아
  실행하지 않았습니다. 단위 테스트(`db-fallback` · `health-route`)가 분기를 덮고 있습니다.
- **소셜 로그인 3사 왕복.** 키가 없어 인가 주소로 나가는 것까지만 확인했습니다.
- **세션 7일 만료 이후의 화면.** 탭 복귀 시 재확인 코드는 들어갔지만 실제 만료는 기다려야 합니다.
- **첨부 업로드·재생.** 이 DB 에는 첨부 파일이 없습니다(원본은 주 체크아웃의 `uploads/`).
