## 1. 왜 만들었나 (Notion 개인 프로젝트 1 · 기획서)

인형뽑기·가챠를 제외한 오락실 게임은 마이너하고 커뮤니티가 분리되어 있어 정보 공유가 어렵습니다. 지도 앱은 **오락실이 어디 있는지까지만** 알려줍니다 — 유저가 알아야 하는 것은 그다음입니다: 내가 하는 게임이 있는가, 기체 상태는 멀쩡한가, 지금 대기가 얼마나 있는가. 이 정보는 커뮤니티·트위터에 흩어져 있습니다.

**해법**: 위치는 등록해 두고, 변하는 것(대기·컨디션·기종 유무)은 **2~3명의 제보만으로도** 실시간에 가깝게 반영합니다. 대기 제보에는 유효기간을 붙여 스스로 만료되게 합니다. 한 문장으로 — **"지금 어디로 갈까"를 점수 하나로 답한다**: 컨디션·대기·거리를 유저가 정한 1·2·3순위로 저울질해 0~100점을 매기고 근거를 행마다 적습니다.

### 네 개의 축 (기획서)

| 축 | 질문 | 핵심 |
|---|---|---|
| 오락실·기종 | 어디에 무엇이 있나 | 이름·주소 검색, 기종 AND 필터, GPS 추적 기준점, 기체 1대 = 1행 |
| 실시간 제보 | 지금 상태는 어떤가 | 제보 4종, 대기 제보 자동 만료, 서로 다른 2명이 모이면 보유 기종 자동 반영 |
| 서열표·채보 | 이 채보는 얼마나 어려운가 | 클리어한 사람만 투표(DB 제약으로 강제), 갈리면 '고유', 표본 적으면 '미정' |
| 커뮤니티 | 남는 이야기는 어디에 | 게임 탭 10개+전체(탭은 테이블이 아니라 컬럼), 본문 삽입 이미지 5장 |

**규모** (기획서 기준): 테이블 22 + 뷰 2 · API 라우트 28 / 핸들러 40 · 화면 6 · 자동 테스트 137 → 이후 증설되어 현재 490건(PERFORMANCE.md 검증 기록).

```

  ├─ 스키마 그룹 5 (센티널 테이블로 멱등) + 마이그레이션 001~041 (schema_migrations 기록)
```

## 3. 데이터 모델 원칙 (기획서 "스키마에 박혀 있습니다" 절)

애플리케이션 검증이 뚫려도 DB가 막고, 코드를 고쳐도 규칙이 흔들리지 않게 — 규칙은 스키마에 둡니다.

1. **제보는 덮어쓰지 않고 쌓기** — 대기 인원을 UPDATE하면 언제 적인지·몇 명이 같은 말을 했는지가 사라짐. `machine_reports`는 append-only, "지금 상태"는 뷰(`machine_live` · `cabinet_condition`)가 만듭니다.
2. **기체 1대가 1행** — 대수를 숫자 한 칸으로 두면 "한쪽 발판만 죽은 오락실"을 표현할 자리가 없음. `arcade_cabinets(arcade_id, machine_id, cabinet_no)`.
3. **소셜 신원은 계정 밖에** — `players`에 provider 칸을 두면 "둘 중 하나만"이 되어 계정이 갈라짐. `player_identities(provider, provider_uid) → players`, 여러 신원이 한 계정을 가리킴.
4. **이메일로 계정을 합치지 않음** — 제공자마다 이메일 검증 여부가 달라, 미검증 이메일 병합은 남의 계정을 가져가는 길. `player_identities.email`은 참고용 사본.
5. **읽는 값은 캐시하고 쓸 때만 갱신** — 평점·투표 집계·댓글 수는 읽기 압도적. `recalc_arcade_rating` · `recalc_chart_stats` · `recalc_post_stats` 함수가 변경 순간에만 다시 씀.
6. **게임별 차이는 코드가 아니라 테이블** — 등급 단계 수·모드·버전·난이도·말머리를 CHECK에 박으면 항목 추가에 마이그레이션이 필요. `tier_grades` · `machine_modes` · `game_versions` · `machine_difficulties` · `board_categories`. 행이 없으면 그 축의 선택기·표시가 화면에서 사라지는 것까지 같은 규칙(펌프에 버전 선택기 없음, 사볼에 모드 선택기 없음, 펌프 칩에 난이도 대괄호 없음).
7. **투표 자격은 DB 제약으로 강제** — `difficulty_votes(player_id, chart_id)`가 `clear_records`를 **복합 FK**로 참조. 클리어 해제 = 투표 CASCADE 소멸.
8. **원본과 조회용 분리** — 사건·설정은 테이블에 보존, "지금 상태"는 뷰·집계 캐시로. 조회 화면이 원본의 계산 방식에 직접 의존하지 않음.

### 제보 한 건이 세 갈래로 (기획서)

```
제보 4종 (있어요·없어졌어요·대기 N명·컨디션 1~5)
  → INSERT → machine_reports (append-only, 수정 없음·삭제는 관리자만)
      ├─ [유효기간 안의 행만] → machine_live · cabinet_condition (뷰) — 상세·목록·전국 피드가 같은 값
      ├─ [서로 다른 제보자 2명] → arcade_machines 실변경 (되돌리기는 관리자만)
      └─ [대기 제보 만료] → 행째 삭제 — 20시간 전 대기 5명은 아무에게도 쓸모없음
```
유효기간·임계값은 코드가 아니라 `report_settings` 한 행 — **배포 없이 조정**.

집계 규칙의 근거: 대기는 `MAX`(과소 신고는 줄 서게 만들고, 과대 신고는 집에 머물게 할 뿐 — 오류가 비대칭), 컨디션은 등록값을 제보 1건으로 셈해 정수 반올림(1~5 척도가 "4.67"을 정직하게 주장할 수 없음). 보유 합의는 **마지막 반대 제보 이후의** 서로 다른 제보자만 셈(3년 전 "있어요" 2건이 오늘의 "없어졌어요"를 영구히 이기면 안 됨) + 익명 제외(한 명이 새로고침으로 임계값을 채울 수 있음).

### 서열표의 특수패턴 진화 (마이그레이션 040 → 041)

040이 `charts.is_special` 불리언을 추가하며 헤더에 스스로 악용 위험("한 명이 모두의 것을 뒤집는다")을 적었고, 041이 그 경고대로 **1인 1표 `special_marks` + `tier_settings.special_min`(기본 3) 합의제**로 전환. `special_min`을 `min_votes`와 분리한 이유 — "평균을 신뢰할 표본"과 "기믹이라는 합의"는 다른 판단이라 독립 튜닝 필요. 버킷팅은 읽기 시점(`tierCodeOf`)이라 플래그를 꺼도 재계산 없이 원 등급 복원.

## 4. 계정과 로그인 (기획서)

들어오는 길은 셋(아이디/비밀번호 · 회원가입 · Google/카카오/네이버), 나오는 것은 **세션 쿠키 한 장**. 로그인은 선택 — 둘러보기·제보는 로그인 없이도 됩니다.

- OAuth 셋 다 인가 코드 흐름 — 차이는 주소·프로필 JSON 모양뿐이라 라우트 한 벌(`/api/auth/oauth/[provider]`)이 처리. **state 쿠키**로 콜백 검증(없으면 남이 만든 `?code=` 링크로 남의 계정에 로그인됨), Google·카카오는 **PKCE(S256)**. 키는 어느 것도 클라이언트로 안 나감(`NEXT_PUBLIC_` 변수 0개).
- 가입 즉시 로그인(방금 정한 비밀번호를 다시 치게 하는 화면은 아무것도 확인해 주지 않음). 가입·로그인 레이트리밋 키 분리.
- **알려진 미완**: 게시판 수정·삭제 권한이 아직 클라이언트가 보낸 `playerId`를 신뢰(남의 글은 403이지만 playerId를 바꿔 보내면 통과). 관리자 경로와 즐겨찾기만 세션이 근거. 남은 일은 각 API가 쿼리스트링 대신 세션을 보게 하는 것 — 제보 어뷰징 방어·신고·차단도 같은 자리에 걸려 있음. 또한 **이메일 등 본인 인증 수단이 미구현** — 인증 메일·비밀번호 찾기·계정 복구 경로가 없음.

## 5. 챗봇과 RAG (RAG_적용_정리.md · `app/api/chat/route.ts`)

현재 구조는 **도구 호출형 검색**: Gemini가 필요 시 `search_arcades` · `search_reports` · `search_posts` · `googleSearch`를 호출. 전형적 RAG(답변 전 검색 주입)와 달리 모델이 먼저 도구 호출을 결정합니다.

- **의도 분기는 클라이언트에서**(`isArcadeSearchIntent`) — 오락실 추천은 API 없이 1·2·3순위 폼 → `lib/recommend.ts` 순수 계산. 키가 없어도 동작해야 하고 분기는 결정적이어야 하므로.
- 시스템 프롬프트를 요청 시점에 DB의 리듬 기종 목록으로 조립 — 답변 범위가 데이터를 따라 움직임. "최신" 질문엔 Google 검색 강제 + 기준 버전 명시.
- **제보 부재의 해석 규칙**(RAG 문서): 제보가 없다는 것은 상태가 좋다는 뜻이 아니라 **최근 제보가 없다는 뜻** — "오락실 B는 지금 한산합니다"는 금지된 답변.
- 향후 계획(RAG 문서): 1단계 기존 SQL 검색 함수를 재사용하는 키워드 RAG(벡터 DB 없이) → 데이터가 쌓이면 2단계 임베딩 검색. 429 대응은 backoff·재시도 상한·컨텍스트 압축과 병행.
- 429 이력: Gemini 무료 플랜에서 429 지속(Notion 3) → API 재연결 + 탐색·예외처리 강화(Notion 4·5)로 해소.

## 6. 실데이터 파이프라인 (커밋 `ab5f77a`~ · Notion 2·4·5)

오락실 목록은 손으로 넣은 것이 아니라 수집·검증 파이프라인의 산출물입니다.

1. **Naver 지역검색(API HUB)** — developers.naver.com 종료 후 NCP 대체 API로 전환(Notion 2의 "클로드가 이전을 모름" 이슈가 발단). 709곳 반영.
2. **공공데이터 LOCALDATA** 청소년게임제공업 인허가 — 1,188곳 반영. 행안부 API의 "정제되지 않은 유령값"(Notion 3) 대응: 영업상태 코드+상태명 이중 판정, 상호명 기반 뽑기방 분류(`classifyByName` — 면적·기기수로는 구분 불가 판명).
3. **검증·클리닝 3회** — 1차 150여 곳 삭제(Notion 4), 누적 약 700곳 유령 좌표 삭제(Notion 5). `lib/arcade-verify.ts`: 지역 축약·query 조합·구조 질의로 Naver 지도에 실존하는지 판정(`found/absent/inconclusive`), 반경 40m 매칭.
4. **좌표 보정** — 지역검색·지오코딩은 도로명 주소의 *입구점*을 반환해 넓은 건물 안쪽 매장과 수십 m 어긋남 → VWorld 건물 폴리곤 **면적 가중 중심점**으로 보정(첫 꼭짓점 기준 상대 좌표로 계산 — 원시 lat/lng를 신발끈 공식에 넣으면 파국적 상쇄로 건물 밖 수십 m 이탈, 실측).

## 7. 주요 설계 결정 기록 (ADR 요약)

| 결정 | 대안 | 채택 이유 |
|---|---|---|
| 리치 본문을 HTML이 아닌 **JSON(RichDoc)** 저장 | HTML + 새니타이저 | 출력 단 새니타이저 불요, `dangerouslySetInnerHTML` 0회, 스타일 값 닫힌 집합. 평문 투영을 병존시켜 검색·미리보기·챗봇·레거시 호환 |
| 에디터는 **Tiptap** | contenteditable 수제 | 선택 서식·undo·한글 IME 조합이 수제가 썩는 지점. 서버가 같은 `normalizeDoc`을 재실행해 우회 주입 차단 |
| 캐시는 라우트가 아닌 **데이터 계층 함수** | 라우트 캐시 / `unstable_cache` | `/api/tier`는 참조+사용자 데이터 혼합 응답 — 라우트 캐시는 남의 기록 유출. `unstable_cache`는 요청 컨텍스트 밖(테스트·스크립트)에서 불변식 위반 (PERFORMANCE.md) |
| 게시판 탭은 테이블이 아닌 **컬럼**(`posts.machine_id`) | 게임별 테이블 | '전체' 탭이 10-way UNION이 되는 것을 방지 |
| 업로드는 `public/` 밖 + **매직 바이트 판정** | 정적 서빙 + 확장자 신뢰 | 비공개 규칙이 생겨도 자리가 한 곳, 확장자·Content-Type은 클라이언트 통제물 |
| 지도 마커는 **커스텀 OverlayView** | 기본 Marker | left/top 리플로우 제거, 풀링·컬링·디핑 가능 ([성능 리포트](PERF-A11Y-REPORT.md)) |
| 좋아요는 단일 **토글 엔드포인트** | on/off 쌍 | DB 현재 상태가 정본 — 두 탭 desync 불가 |
| 반경 검색은 당분간 **SQL haversine** | PostGIS | 실측 13ms로 병목 아님(PERFORMANCE.md가 재발굴 금지 명시). 스키마 헤더에 PostGIS 이관 경로 문서화 |
| 만료 대기 제보는 **행째 삭제** | 숨김 처리 | 낡은 대기값은 역사가 아니라 오답이고, 24시간 피드에서 신선한 제보를 밀어냄. 스케줄러 없이 읽기/쓰기 시 purge |

## 8. 사건·사고와 재발 방지 (Notion 개인 프로젝트 5)

- **DB 소실 사고**: 공지 기능 수정 중 Claude가 DB를 날림 → 기존 PGlite를 재이관해 복구 → **작업마다 백업을 지시하는 프롬프트** 확립(현재 `backups/` · `backup-db-*` 폴더 운영, 커밋 `ab5f77a`가 백업 폴더를 커밋 대상에서 제외).
- **낡은 서버 측정 사고**: 3000 포트에 2시간 전 프로세스가 남아 옛 빌드를 측정 → 부하테스트 전 포트 점검을 절차화(PERFORMANCE.md).

## 9. 열린 문제

- **허위 제보** (Notion 1·5에서 반복 제기): 시스템이 유저 제보로 굴러가므로 거짓 제보의 근본 해결책이 없음. 현재 완화 장치 — 보유 반영은 서로 다른 제보자 2명 합의 + 익명 제외, 대기 자동 만료, 관리자 삭제. 남은 방향은 세션 기반 신원 + 신고·차단(4절의 미완 항목과 동일 지점).
- **API 권한의 세션 전환** — 게시판·제보·투표의 `playerId`를 세션 유도로 교체.
- **기기 버전·대수의 최신성** (Notion 5): 방문·제보·운영자 제공 없이는 알 수 없음 — 제보 축이 감당할 몫.
- 펌프 외 리듬게임 서열표(정보 수집·자문 필요), 업로드 고아 파일 정리 배치, 커뮤니티 저장소 Redis 전환 검토(Notion 5).
